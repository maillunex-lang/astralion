# Дорожная карта «Астралион: Наследие звёзд»

## Паспорт проекта

- Платформа: Android, горизонтальная ориентация; Godot 4.
- Игровое представление: 3D-объекты в 2.5D; звёздный фон 2D.
- Управление только кораблём; все атаки кораблей и дронов магические.
- Стиль: Anime Space Fantasy Clean Stylized Sci-Fi; Meshy AI для 3D-ресурсов.
- Мир: расширяемая галактика, первая система с насыщенными областями и коридорами.
- Сервер авторитетен; VPS, реальные игроки, позднее правдоподобные ИИ-пилоты.
- Технологии в исходниках: не установлены, потому что исходников пока нет.
- Go/PostgreSQL/React/WebSocket/Compose — технические предложения, не принятый стек.
- Архитектурные принципы: модули, стабильные ID, серверные правила, версионированный контент.
- Текущий этап: аудит дерева/документации завершён, переход к фундаменту 01.
- Ближайшая цель: принять конкретный технический ADR для локального онлайн-среза.

Источник требований — GAME.md, точные ссылки на закреплённый снимок в
[DECISIONS_INDEX](DECISIONS_INDEX.md). Технические предложения отделены от утверждений.
Выявлены 92 записи требований/направлений, 5 предложений и 1 технический план.
Четыре раздела не имеют оригинальных ID; их локаторы Lxxxx не являются новыми игровыми ID.
Полный структурный разбор источника выполнен, смысловая сверка выборочная — RISK-021.

## Приоритеты

- P0 — критический фундамент, дорого переделываемые контракты, воспроизводимость и методика измерений.
- P1 — обязательный сквозной игровой прототип и его проверки.
- P2 — расширение основных систем после подтверждения базового цикла.
- P3 — дальнейший контент, сложные режимы и подготовка выпуска.
- P4 — необязательные улучшения; новые необязательные функции в этом пакете не придуманы.

Приоритет следует зависимостям, игровому результату, техническому риску и стоимости переделки.
Номер/положение решения в GAME.md не определяет важность.
Приоритет этапа — минимальный приоритет его основных задач; отдельные задачи могут иметь иной P.
Обязательная механика с P2/P3 сохраняется в плане, а не отменяется.

## Статусы

- TODO — реализация не начата.
- IN_PROGRESS — задача действительно выполняется назначенным владельцем.
- PARTIAL — часть результата есть, критерии ещё не подтверждены целиком.
- BLOCKED — известная преграда, требующая отдельного решения или доступа.
- DONE — критерии выполнены и обязательные проверки успешны.
- UNKNOWN — фактическое состояние ещё не установлено.

UNVERIFIED относится к отдельной сборке/проверке, не является дополнительным статусом задачи.
Отсутствующие исходники подтверждены: соответствующие реализации TODO, а не UNKNOWN.
Проценты не используются; по мере дробления задач их количество может измениться.
Канонический статус задачи — в таблице stages; TASK и ROADMAP должны совпадать.
Правила сводного статуса этапа — в README системы; валидатор проверяет согласованность.

## Ворота MVP-0

- Android/Godot, один управляемый корабль и читаемая стартовая область.
- Два реальных игрока видят друг друга; сервер ограничивает движение и хранит позицию.
- Карта, квестовый маркер, автопуть и независимый ограниченный автобой проверены.
- NPC → квест → противник → награда → сохранение → станция пройдены без дюпа.
- Базовая веб-админка и Визуальная студия редактируют реально используемый контент.
- Манифест, фоновая загрузка, целостность и кэш устойчивы к обрыву.
- APK, CI, бэкап/восстановление и замеры имеют реальные артефакты.
- Полный критерий собран в TEST-002; невыполненный обязательный пункт запрещает DONE среза.

В полном объёме MVP-0 не включает ИИ-пилотов, VIP, BP, гачу, рынок, корпорации,
войны, сложные инстансы и весь сюжет; это прямо отделено DEV-FOUNDATION-001.
Первый тест двух клиентов не равен готовому MMO-релизу.

## Как выбрать задачу и открыть минимальный контекст

1. AGENTS → PROJECT_STATE.
2. Если задача не задана — эта ROADMAP и [DEPENDENCIES](DEPENDENCIES.md).
3. Один нужный stages/*.md → один tasks/TASK-ID.md.
4. Только связанные исходники и точечный поиск исходных ID через DECISIONS_INDEX.
5. Читать нужный фрагмент GAME.md при недостатке контекста или противоречии.

Не загружать все этапы, все исходники и весь GAME.md при каждом запуске.
Архитектурный пакет читает ARCHITECTURE; сцена — соответствующий SCENE-DETAIL и канон.
Для обычного исправления уже проверенной механики повторный полный аудит не нужен.
Актуальность: сравнить HEAD, пути diff и commit источника; устаревшие выводы перепроверить.

## Несколько ИИ и завершение сессии

Назначить владельца/ветку/базовый SHA; разные worktree и непересекающиеся allowlist.
Общие документы и контракты интегрирует один владелец, остальные передают handoff.
Не считать коммит подтверждением поведения. После интеграции повторить затронутые проверки.

Перед DONE: проверить diff, выполнить проверки, записать SHA/команды/результаты и ограничения.
Обновить TASK, этап, PROJECT_STATE, CHANGELOG и handoff; эту таблицу при изменении прогресса.
Сохранить нерешённые проблемы, назвать следующий ID, запустить документационный валидатор.
Провал обязательного теста запрещает DONE; непроверенная реализация остаётся PARTIAL/UNKNOWN.
