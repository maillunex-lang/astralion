Эта папка управляет разработкой, а не пересказывает GAME.md.
Игровых исходников в исходном коммите нет; готовность документации не означает готовность игры.

## Как начать новую сессию

Прочитать корневой [AGENTS.md](../../AGENTS.md), PROJECT_STATE, текущий этап
и TASK-файл. ROADMAP нужен при выборе следующей задачи. Исходники открывать по allowlist TASK.
Первая задача: [FOUNDATION-001](tasks/FOUNDATION-001.md).
Для неё достаточно AGENTS → PROJECT_STATE → 01-FOUNDATION → TASK;
ARCHITECTURE и DEPENDENCIES читаются по точечным ссылкам из TASK.
GAME.md целиком при обычной задаче не нужен.

## Правила, действующие и без поддержки AGENTS.md

- GAME.md сохраняется без изменений; исходный commit и хеши — в индексе и SOURCE_MANIFEST.json.
- Утверждённые решения, обязательные направления и технические предложения различаются явно.
- Не придумывать новые механики, цены, баланс, численные бюджеты и правила открытых режимов.
- Сохранять ID и дословный канон. Противоречие записать в RISKS, не решать по догадке.
- Полное чтение источника не запускать автоматически: только первичная индексация,
  крупная архитектурная смена, противоречие или нехватка контекста после индекса.
- Перед кодом проверить зависимости и заполнить TASK: владелец, ветка, точные файлы,
  запреты, критерии и команды. Один проверяемый результат на ограниченную сессию.
- Код, сборка, наличие тестов, успешность тестов и runtime подтверждаются отдельно.
- Не удалять существующие материалы, не устанавливать лишние зависимости,
  не выполнять опасные миграции/production-операции и не помещать секреты в Git.
- Новые документы и отчёты — на русском; техпредложение не меняет игровых требований.
- Не отмечать DONE при обязательной проваленной проверке; отсутствие проверки = UNVERIFIED.

## Статусы и прогресс

| Статус | Значение |
| --- | --- |
| TODO | Реализация не начата |
| IN_PROGRESS | Есть назначенный исполнитель и активная работа |
| PARTIAL | Есть часть реализации или результата, готовность не подтверждена полностью |
| BLOCKED | Известная внешняя преграда/неутверждённое правило не позволяет завершить |
| DONE | Все критерии задачи выполнены и проверки успешны |
| UNKNOWN | Фактическое состояние ещё не установлено |

TODO с незавершённой плановой зависимостью остаётся TODO: это обычная очередь.
BLOCKED означает отдельный нерешённый блокер, а не просто положение в очереди.
UNVERIFIED используется в матрице доказательств, не как статус задачи.
Счёт DONE/всего показывает только число проверяемых задач, не процент готовности MMORPG.
Если все задачи DONE — этап DONE; при всех TODO/BLOCKED и хотя бы одной TODO — этап TODO;
если все BLOCKED — этап BLOCKED; при активной работе — IN_PROGRESS;
при смешанном завершении — PARTIAL; если всё неизвестно — UNKNOWN.
Переходы выполняются вручную с доказательствами; скрипт статусы не меняет.

## Параллельная работа и интеграция

Каждый пакет имеет владельца, ветку `task/<id>` и отдельный worktree при необходимости.
После проверки чистоты дерева: `git worktree add -b task/<id> ../astralion-<id> <базовый-SHA>`.
Это шаблон, не команда с буквальным `<id>`.
Выдать непересекающиеся allowlist; общий протокол сначала закрепить одним коммитом.
Общие документы интегрирует один владелец, остальные передают правки в handoff.
Не редактировать чужой worktree и не подменять тестирование наличием коммита.
После интеграции повторить проверки затронутых компонентов.

## Завершение пакета

Проверить diff и доступные тесты; зафиксировать команду, окружение, SHA, результат и ограничения.
Обновить TASK, этап, PROJECT_STATE, CHANGELOG и handoff; ROADMAP при смене прогресса или фокуса.
Указать остаточные проблемы и следующий ID. При неуспешной проверке DONE запрещён.

## Проверка документации

Из корня: `python3 scripts/check_development_docs.py`.
Без установки пакетов: только стандартная библиотека Python 3.
Регрессионные проверки валидатора: `PYTHONDONTWRITEBYTECODE=1 python3 scripts/test_development_docs.py`.
Проверяются локальные ссылки/якоря, дубли ID, допустимые статусы, зависимости,
циклы задач, зеркала TASK/этапов и их готовность, покрытие исходных ID по манифесту.
Дополнительно: `python3 scripts/check_development_docs.py --source /путь/к/GAME.md`.
Это проверяет байты исходного снимка и извлечение ID, но не заменяет смысловую экспертизу.
Внешние ссылки закреплены на один commit; сетевую доступность офлайн-проверка не гарантирует.

## Экономия контекста и актуальность аудита

Не дублировать большие тексты; искать ID через `rg -n 'SERVER-003' docs/development`.
Сначала сверить HEAD, изменившиеся файлы и SOURCE_MANIFEST; затем повторить только затронутый аудит.
При новой реализации нельзя автоматически сохранять вывод «кода нет» из b3ed870.
Оценка объёма контекста и допущения — в handoffs/INITIAL-AUDIT.md.
Markdown достаточно: отдельная инфраструктура памяти не требуется.
